# Классификация твитов о бедствиях

Модель получает текст твита и предсказывает одну из двух меток. Класс `1` обозначает сообщение о реальном бедствии, класс `0` включает остальные твиты. Использованы данные соревнования [Natural Language Processing with Disaster Tweets](https://www.kaggle.com/competitions/nlp-getting-started/data).

## Данные и оценка

- В `train.csv` 7 613 твитов с метками. К классу `1` относится 42,97% строк. В полях `text` и `target` пропусков нет, а в `location` отсутствует треть значений. Все модели получают только `text`.
- Медианная длина твита составляет 107 символов и 15 слов при разбиении по пробелам. Твиты класса `1` чуть длиннее по медиане числа символов (115 против 101). Графики и подробные расчёты находятся в [EDA-ноутбуке](Text_classification.ipynb).
- У 18 текстов встречаются обе метки. Из 7 613 строк исключены все такие тексты и лишние экземпляры повторов с согласованной меткой. После очистки осталось 7 485 твитов.
- Зафиксировано групповое стратифицированное разбиение примерно 80/20 с `seed=42`. Группу образуют твиты с одинаковой последовательностью токенов после декодирования HTML, замены ссылок и упоминаний на маркеры, приведения к нижнему регистру и токенизации. Каждая группа целиком назначается одной выборке. Первый фолд `StratifiedGroupKFold` из пяти дал 5 987 твитов для обучения и 1 498 для валидации, из них 638 положительных. `test.csv` содержит 3 263 твита без `target`.
- При первоначальном разбиении совпадения искали по исходному тексту. После нормализации 162 валидационных твита совпали с обучающими. Групповое разбиение устраняет пересечение по этой последовательности токенов. Метрики ниже рассчитаны на новом разбиении.
- Основная метрика — бинарный F1 по классу `1`, как в соревновании. Также рассчитаны precision и recall для класса `1`, accuracy и элементы матрицы ошибок. [Метрика соревнования](https://www.kaggle.com/c/nlp-getting-started/#evaluation)

## Эксперименты

### 1. Классические модели

Логистическая регрессия служит линейным ориентиром. Для нелинейной модели выбран LightGBM, градиентный бустинг над деревьями с поддержкой разреженных признаков. Обе модели получают одну и ту же матрицу признаков для каждого опыта. [LightGBM](https://lightgbm.readthedocs.io/en/v4.6.0/Features.html#sparse-optimization)

Базовый TF-IDF использует отдельные токены в нижнем регистре. Сначала по отдельности проверяем удаление английских стоп-слов, стемминг Snowball, лемматизацию WordNet с учётом части речи, нормализацию ссылок и упоминаний и добавление биграмм. Затем сравниваем нормализацию в комбинациях со стоп-словами, стеммингом, лемматизацией и со стоп-словами плюс стеммингом. В последнем опыте стоп-слова удаляются до стемминга. Ссылки и упоминания при нормализации заменяются маркерами. Для сравнения также используется BoW на униграммах.

Словарь и IDF строятся на обучающей части. Для каждой конфигурации векторизатор и классификатор обучаются заново. При выборе классификатора для эмбеддингов берётся алгоритм, получивший лучший F1 на классическом этапе.

### 2. Эмбеддинги и классический классификатор

Выбор эмбеддера сделан по столбцу **Classification (12)** исторической англоязычной таблицы MTEB. Сравнивались три компактных энкодера с векторами размерности 384.

| Модель | MTEB Classification (12) |
|---|---:|
| BAAI/bge-small-en-v1.5 | **74,14** |
| intfloat/e5-small-v2 | 72,94 |
| thenlper/gte-small | 72,31 |

BGE показал наибольший результат среди этих кандидатов. Значения относятся к задачам внешнего бенчмарка. [Таблица BGE](https://huggingface.co/BAAI/bge-small-en-v1.5#evaluation) · [Таблица GTE](https://huggingface.co/thenlper/gte-small#metrics) · [MTEB](https://huggingface.co/spaces/mteb/leaderboard)

Исходные твиты пропускаются через токенизатор модели. Для каждого твита берётся выходное представление первого токена и применяется L2-нормализация. Энкодер заморожен. Алгоритм из первого этапа заново обучается на 384-мерных векторах. [Карточка BGE](https://huggingface.co/BAAI/bge-small-en-v1.5)

### 3. Дообучение BERT

Выбран `google/bert_uncased_L-4_H-512_A-8` (BERT-Small). Англоязычный энкодер с 4 слоями и скрытой размерностью 512 подходит для коротких твитов и позволяет воспроизвести обучение на CPU. Используется `AutoModelForSequenceClassification` из Transformers. К предобученному энкодеру добавляется голова для двух классов. При обучении обновляются веса энкодера и головы. [Карточка BERT-Small](https://huggingface.co/google/bert_uncased_L-4_H-512_A-8)

В модель подаётся исходный текст. Токенизатор выполняет WordPiece-токенизацию, ограничение до 96 токенов и динамическое дополнение до максимальной длины в батче. В очищенных данных максимальная длина составила 84 токена с учётом спецтокенов у обоих трансформеров. Используем AdamW с learning rate `5e-5`, линейным расписанием с разогревом и батчем 32. Из трёх эпох выбираем эпоху с лучшим F1 на валидации. [Документация Transformers](https://huggingface.co/docs/transformers/v4.57.1/en/tasks/sequence_classification)

## Результаты

### Классический NLP

| Признаки | F1 логистической регрессии | F1 LightGBM |
|---|---:|---:|
| TF-IDF, базовый | 0,7074 | 0,6850 |
| TF-IDF, удаление стоп-слов | 0,7051 | 0,6583 |
| TF-IDF, стемминг | 0,7399 | 0,7308 |
| TF-IDF, лемматизация | 0,7334 | 0,7309 |
| TF-IDF, нормализация ссылок и упоминаний | 0,7073 | 0,6825 |
| TF-IDF, нормализация + удаление стоп-слов | 0,7086 | 0,6732 |
| TF-IDF, нормализация + стемминг | 0,7086 | 0,7273 |
| TF-IDF, нормализация + лемматизация | 0,7415 | 0,7360 |
| TF-IDF, нормализация + удаление стоп-слов + стемминг | 0,7081 | 0,6952 |
| TF-IDF, униграммы и биграммы | 0,7230 | 0,6789 |
| BoW, униграммы | 0,7186 | 0,6969 |

Лучшая классическая конфигурация — TF-IDF, нормализация + лемматизация + логистическая регрессия с F1 = 0,7415. Полная цепочка со стоп-словами и стеммингом дала F1 = 0,7081 с логистической регрессией. У LightGBM лучший F1 = 0,7360 в конфигурации «TF-IDF, нормализация + лемматизация».

### Сравнение трёх подходов на CPU

| Лучшая конфигурация подхода | Precision | Recall | F1 | Accuracy | Инференс, мс/твит |
|---|---:|---:|---:|---:|---:|
| TF-IDF, нормализация + лемматизация + логистическая регрессия | 0,8104 | 0,6834 | 0,7415 | 0,7971 | 0,4429 |
| BGE + логистическая регрессия | 0,8221 | 0,7821 | **0,8016** | 0,8351 | 9,8719 |
| BERT-Small, эпоха 2 | 0,8308 | 0,7696 | 0,7990 | 0,8351 | 4,3579 |

Лучший F1 класса `1` показала конфигурация **BGE + логистическая регрессия** (0,8016). Она нашла 499 из 638 твитов класса `1`.

Самая быстрая конфигурация на CPU — **BoW, униграммы + логистическая регрессия** (0,0136 мс на твит в пересчёте с батча, F1 = 0,7186).

Для сравнения скорости измерено время от исходного текста до метки на первых 256 твитах валидации в батчах по 32, после прогрева. Указана медиана трёх прогонов, делённая на число твитов. Время включает подготовку текста, TF-IDF или токенизацию, собственно прогноз и перенос результата на CPU при использовании CUDA. Загрузка весов исключена из замера. Все показанные замеры сделаны на AMD EPYC 9V74 с лимитом в 6 потоков. `fit_seconds` отражает время подготовки обучающих признаков и обучения. Для BERT в него входит валидация между эпохами.

Полная таблица с матрицами ошибок и временем обучения находится в [results/metrics.csv](results/metrics.csv), метрики по эпохам — в [results/finetune_history.csv](results/finetune_history.csv). [results/run_info.json](results/run_info.json) содержит версии библиотек, конфигурацию и контрольную сумму разбиения.

### Как улучшить результат

1. Подобрать на внутренней кросс-валидации коэффициент регуляризации логистической регрессии и порог положительного класса. Это позволяет управлять числом пропусков и ложных тревог в соответствии с задачей.
2. Проверить символьные n-граммы в TF-IDF для опечаток, хештегов и разговорных написаний. При удалении стоп-слов отдельно проверить сохранение отрицаний.
3. Сравнить BERT-Small с трансформером, предобученным на твитах, например Twitter-RoBERTa. Затем повторить оценку на отдельной размеченной выборке или с внешним тестом. [Карточка Twitter-RoBERTa](https://huggingface.co/cardiffnlp/twitter-roberta-base)

Один набор валидации использован для выбора классической конфигурации и эпохи BERT. Приведённые значения описывают это разбиение и могут быть оптимистичны как оценка на новых данных. Для независимой оценки понадобится отдельный набор с метками.

## Запуск

Распакуйте проект, положите исходные `train.csv` и `test.csv` в папку `data/` и откройте терминал в корне проекта. Для существующего окружения PyCharm используйте его `python.exe`. Ниже команды PowerShell для Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m nltk.downloader wordnet averaged_perceptron_tagger_eng
.\.venv\Scripts\python.exe -m tweetclf all
```

При первом запуске BGE и BERT загрузятся с Hugging Face в `model_cache/`. При медленном скачивании задайте `$env:HF_HUB_DOWNLOAD_TIMEOUT = "120"` в том же терминале перед запуском. Значение `device: auto` выбирает CUDA, если она доступна для PyTorch, и CPU в остальных случаях. Для замеров CPU явно задайте `--device cpu`. Для установки сборки с CUDA используйте команду для PyTorch 2.8.0 и подходящей версии CUDA. [Сборки PyTorch](https://pytorch.org/get-started/previous-versions/#v280) · [Переменные Hugging Face Hub](https://huggingface.co/docs/huggingface_hub/package_reference/environment_variables#hf_hub_download_timeout)

Скрипт позволяет запускать этапы по отдельности. Для эмбеддингов предварительно нужен результат классического этапа с той же конфигурацией.

```powershell
.\.venv\Scripts\python.exe -m tweetclf classic
.\.venv\Scripts\python.exe -m tweetclf embeddings
.\.venv\Scripts\python.exe -m tweetclf finetune
```

В PyCharm откройте `Text_classification.ipynb` из корня проекта и выберите то же Python-окружение. Структура проекта:

| Путь | Содержимое |
|---|---|
| `Text_classification.ipynb` | Загрузка данных, EDA, повторы и разбиение |
| `configs/experiment.yaml` | Разбиение, варианты предобработки и параметры моделей |
| `tweetclf/` | Команды запуска, подготовка данных, обучение и измерение метрик |
| `results/` | Таблица экспериментов, история дообучения и сведения о запуске |
| `requirements.txt` | Зависимости Python |
